1. Цели работы

Попрактиковаться в написании запросов в консоли запросов и научиться:

🔗

Соединения

Создавать и настраивать соединения между таблицами (ВНУТРЕННЕЕ СОЕДИНЕНИЕ … ПО …).

🎛

Параметры

Зависеть от заданных параметров: &Дата, &Склад, &ВидЦены.

▦

Виртуальные таблицы

Ставить отборы прямо в параметрах виртуальных таблиц: Остатки(&Дата, Склад = &Склад).

Что делаем: 1) получение номенклатуры и её остатков запросом; 2) использование временной таблицы в отборе по остаткам.

2. Подготовка: консоль и параметры

📌 Где взять консоль запросов Обычно: Администрирование → Сервис → Консоль запросов (в некоторых конфигурациях пункт называется просто «Консоль запросов» или открывается внешней обработкой). Окно состоит из текста запроса слева и дерева объектов конфигурации справа — из него можно вставлять имена таблиц двойным щелчком.

Как задать параметры запроса

  • В тексте напишите обращение к параметру: &Дата, &Склад, &ВидЦены (символ & обязателен).
  • Откройте окно параметров консоли (кнопка «Параметры запроса» на панели — часто с иконкой &; в некоторых версиях это отдельная вкладка справа).
  • Добавьте параметр, укажите Тип (Дата, СправочникСсылка.Склады, СправочникСсылка.ВидыЦен…) и Значение.
  • Нажмите Выполнить (клавиша F5 в большинстве консолей).
💡 Совет Тип параметра должен совпадать с типом поля, с которым он сравнивается. Сравниваете со складом — тип «СправочникСсылка.Склады». Не тот тип → ошибка приведения типов.

3. Задание 1. Номенклатура и её остатки

Менеджер просит: вывести остатки товаров на текущую дату (колонки «Код», «Наименование», «Остаток»), а позже понадобится то же самое на указанную дату и по указанному складу. Решаем по шагам.

1

Сначала — просто номенклатура с остатками

Соединяем справочник номенклатуры с виртуальной таблицей остатков. Оставляем только те позиции, у которых остаток положительный.

ВЫБРАТЬ
    Номенклатура.Код КАК Код,
    Номенклатура.Наименование КАК Наименование,
    Остатки.КоличествоОстаток КАК Остаток
ИЗ
    Справочник.Номенклатура КАК Номенклатура
        ВНУТРЕННЕЕ СОЕДИНЕНИЕ РегистрНакопления.ТоварыНаСкладах.Остатки КАК Остатки
        ПО Номенклатура.Ссылка = Остатки.Номенклатура
ГДЕ
    Остатки.КоличествоОстаток > 0

Пояснения

  • ИЗ Справочник.Номенклатура — откуда берём строки. Псевдоним КАК Номенклатура — короткое имя таблицы в тексте.
  • ВНУТРЕННЕЕ СОЕДИНЕНИЕ … ПО Номенклатура.Ссылка = Остатки.Номенклатура — «мостик» между таблицами: строка справочника соединяется с её строкой остатков. Внутреннее соединение оставляет только совпавшие пары — то есть только номенклатуру, по которой остатки есть.
  • ГДЕ … > 0 — отсекает нулевые и отрицательные остатки.
⚠️ Так пока не сработает для «суммы по всем складам» Виртуальная таблица Остатки() выдаёт отдельную строку на каждый склад. Если на двух складах по 3 шт — вы увидите две строки по 3, а не одну по 6. Исправляем на следующем шаге.
2

Суммируем остатки по всем складам

Добавляем СУММА(...) и группировку — теперь одна строка на номенклатуру со складовым итогом.

ВЫБРАТЬ
    Номенклатура.Код КАК Код,
    Номенклатура.Наименование КАК Наименование,
    СУММА(Остатки.КоличествоОстаток) КАК Остаток
ИЗ
    Справочник.Номенклатура КАК Номенклатура
        ВНУТРЕННЕЕ СОЕДИНЕНИЕ РегистрНакопления.ТоварыНаСкладах.Остатки КАК Остатки
        ПО Номенклатура.Ссылка = Остатки.Номенклатура
СГРУППИРОВАТЬ ПО
    Номенклатура.Ссылка,
    Номенклатура.Код,
    Номенклатура.Наименование
ИМЕЮЩИЕ
    СУММА(Остатки.КоличествоОстаток) > 0

Пояснения

  • СГРУППИРОВАТЬ ПО — складываем «внутри» каждой номенклатуры. Все колонки без СУММА(...) обязаны попасть в группировку — иначе ошибка «поле не входит в список группировки».
  • ИМЕЮЩИЕ — это фильтр после суммирования (как ГДЕ, только для агрегатов). В ГДЕ писать СУММА(...) > 0 нельзя — там агрегатов ещё не существует.
3

Добавляем параметры: период и склад

Менеджер прав: данные нужны «на дату» и «по складу». Параметры подставляются в параметры виртуальной таблицы — это и есть главный приём работы с Остатки(...).

ВЫБРАТЬ
    Номенклатура.Код КАК Код,
    Номенклатура.Наименование КАК Наименование,
    СУММА(Остатки.КоличествоОстаток) КАК Остаток
ИЗ
    Справочник.Номенклатура КАК Номенклатура
        ВНУТРЕННЕЕ СОЕДИНЕНИЕ РегистрНакопления.ТоварыНаСкладах.Остатки(&Дата, Склад = &Склад) КАК Остатки
        ПО Номенклатура.Ссылка = Остатки.Номенклатура
СГРУППИРОВАТЬ ПО
    Номенклатура.Ссылка,
    Номенклатура.Код,
    Номенклатура.Наименование
ИМЕЮЩИЕ
    СУММА(Остатки.КоличествоОстаток) > 0

Пояснения

  • Остатки(&Дата, Склад = &Склад) — два параметра виртуальной таблицы:
    • &Дата — на какой момент считать остаток. «На начало месяца» → поставьте 01.11.2026; «на текущий момент» → сегодняшняя дата. Без параметра остатки берутся «на сейчас».
    • Склад = &Склад — отбор по измерению виртуальной таблицы. По совету курса отборы по измерениям задаются именно здесь, в скобках, а не в ГДЕ.
  • Дата — только через параметр. Дату виртуальной таблицы нельзя «поймать» в ГДЕ: без неё вы получите остатки на текущий момент, а не на нужную дату.
  • Склад в ГДЕ формально можно (он есть среди колонок результата), но для оценки и для скорости правильнее — в параметрах виртуальной таблицы.
📌 Как быть с «остатками по всем складам»? Если склад конкретный — используйте Остатки(&Дата, Склад = &Склад). Если нужно «по всем складам» — вызывайте Остатки(&Дата) без отбора (параметр &Склад тогда не нужен). Так вы получите и «как у менеджера на сегодня», и «на 1-е число по нужному складу» одним и тем же запросом — меняются только значения параметров в консоли.

Как задать значения в консоли

  • &Дата → Тип: Дата, Значение: 24.11.2026 (или 01.11.2026 для начала месяца).
  • &Склад → Тип: СправочникСсылка.Склады, Значение: выбрать нужный склад из списка.
  • Нажать Выполнить.

Примерный вид результата

КодНаименованиеОстаток
000000001Galaxy Moon X105
000000003Crystal Whirl Max1510
Самопроверка

Что оценивается → что проверить:

  • ✅ В выводе есть «Код», «Наименование», «Остаток» — и только номенклатура с ненулевым остатком;
  • ✅ Данные корректны: суммы по складам сходятся (можно сверить с отчётом «Остатки товаров»);
  • ✅ Запрос выполняется при любых значениях &Дата и &Склад — значит, параметры установлены правильно.

4. Задание 2. Временная таблица в отборе по остаткам

Теперь один запрос из двух пакетов: первый запоминает номенклатуру с «оптовой» ценой во временную таблицу, второй берёт остатки только по этой номенклатуре и добавляет цену в вывод.

📌 Что такое «пакеты запроса» Текст запроса — это последовательность операторов, разделённых точкой с запятой ;. Результат пакета №1 (временная таблица) доступен в пакете №2. Временная таблица живёт только во время выполнения — это «черновик», который не сохраняется в базе.
1

Пакет 1: номенклатура с оптовой ценой → во временную таблицу

// Пакет 1 — номенклатура, у которой на текущую дату есть цена вида «Оптовая»
ВЫБРАТЬ
    Цены.Номенклатура КАК Номенклатура,
    Цены.Цена КАК ЦенаОптовая
ПОМЕСТИТЬ втНоменклатураСОптовойЦеной
ИЗ
    РегистрСведений.ЦеныНоменклатуры.СрезПоследних(&Дата, ВидЦены = &ВидЦены) КАК Цены
ГДЕ
    Цены.Цена > 0
;

Пояснения

  • СрезПоследних(&Дата, ВидЦены = &ВидЦены) — виртуальная таблица: «последняя цена на дату». Оба отбора — дата и вид цены — задаются в параметрах виртуальной таблицы:
    • &Дата — на какую дату смотрим (сегодня → текущая дата);
    • ВидЦены = &ВидЦены — фильтр по измерению «Вид цен»; в параметрах консоли задайте &ВидЦены = элемент «Оптовая».
  • ПОМЕСТИТЬ втНоменклатураСОптовойЦеной — результат кладём во временную таблицу. Имя «вт…» — договорённость разработчиков, не требование языка.
  • ГДЕ Цена > 0 — гарантия «цена действительно установлена». Если в вашей базе нулевых цен не бывает, условие можно убрать.
  • ; в конце — обязательный разделитель пакетов! Без него пакет 2 «не увидит» временную таблицу.
💡 Если в базе иначе Когда вид цены — не отдельный справочник, а перечисление, параметр &ВидЦены просто получит другую типизацию. Ещё вариант «без параметра»: ВидЦены = ЗНАЧЕНИЕ(Справочник.ВидыЦен.Оптовая) — но параметр гибче: одной настройкой консоли переключаетесь с «Оптовой» на «Розничную».
2

Пакет 2: остатки + отбор по временной таблице + цена в выводе

// Пакет 2 — остатки только по номенклатуре из пакета 1, с оптовой ценой
ВЫБРАТЬ
    Номенклатура.Наименование КАК Наименование,
    Остатки.Остаток КАК Остаток,
    ВТНоменклатуры.ЦенаОптовая КАК ЦенаОптовая
ИЗ
    втНоменклатураСОптовойЦеной КАК ВТНоменклатуры
        ВНУТРЕННЕЕ СОЕДИНЕНИЕ (ВЫБРАТЬ
                Остатки.Номенклатура КАК Номенклатура,
                СУММА(Остатки.КоличествоОстаток) КАК Остаток
            ИЗ
                РегистрНакопления.ТоварыНаСкладах.Остатки(&Дата) КАК Остатки
            СГРУППИРОВАТЬ ПО
                Остатки.Номенклатура) КАК Остатки
        ПО ВТНоменклатуры.Номенклатура = Остатки.Номенклатура
ГДЕ
    Остатки.Остаток > 0
УПОРЯДОЧИТЬ ПО
    Наименование

Пояснения

  • Из чего состоит ИЗ: слева — временная таблица из пакета 1 (псевдоним ВТНоменклатуры), справа в скобках — подзапрос, который собирает остатки: сначала СУММА по складам, как в задании 1.
  • ПО ВТНоменклатуры.Номенклатура = Остатки.Номенклатура — и есть «отбор по списку номенклатуры из первого пакета»: внутреннее соединение оставит только те остатки, у которых номенклатура «есть в ценовой таблице». Без ПО соединение не заработает (да и синтаксически не соберётся).
  • ЦенаОптовая в выводе — пришла из левой таблицы соединения; её же можно использовать для сортировки или фильтра (ГДЕ ВТНоменклатуры.ЦенаОптовая > 1000).
  • &Дата используется в обоих пакетах — один параметр на весь запрос; задаётся один раз в консоли.
⚠️ Альтернатива вместо соединения Шаг 3 задания можно закрыть и через отбор «В (…)»:
ГДЕ Остатки.Номенклатура В (ВЫБРАТЬ Номенклатура ИЗ втНоменклатураСОптовойЦеной)
Но соединение — основной способ, который проверяется по критериям («Правильность настройки соединения таблиц»), поэтому пишем через ВНУТРЕННЕЕ СОЕДИНЕНИЕ … ПО.

НаименованиеОстатокЦенаОптовая
Galaxy Moon X105100 000

Crystal Whirl Max151075 000
Короб упаковочный225
Самопроверка

Что оценивается → что проверить:

  • ✅ В выводе ровно три колонки: «Наименование», «Остаток», «ЦенаОптовая»;
  • ✅ Нет позиций без оптовой цены и без остатка (внутреннее соединение + > 0);
  • ✅ Соединение настроено по «Номенклатура = Номенклатура» (не по наименованию строкой!);
  • ✅ Параметры &Дата и &ВидЦены заданы, запрос выполняется без ошибок.

5. Частые ошибки

❌ «Параметр &Дата не задан» (или &Склад, &ВидЦены)
Параметр есть в тексте, но не задан в окне параметров консоли. Откройте «Параметры запроса», добавьте его, укажите тип и значение, выполните снова.
❌ «Ошибочное выражение: поле не входит в список группировки»
Вы используете СУММА(...), но не добавили СГРУППИРОВАТЬ ПО. Все колонки без агрегатной функции должны быть в списке группировки.
❌ «В контексте агрегатных функций можно использовать только агрегатные функции»
СУМма(...) > 0 написано в ГДЕ. Перенесите условие в ИМЕЮЩИЕ — оно применяется после группировки.
❌ Дубли строк: одна номенклатура несколько раз
Забыли СГРУППИРОВАТЬ ПО — виртуальная таблица выдаёт строку на каждый склад. Либо соединение написано «в лоб» без критерия ПО (тогда каждая строка с каждой — так нельзя).
❌ «Имя таблицы не определено: втНоменклатураСОптовойЦеной»
Пакеты не разделены ; или временная таблица создана после того, как к ней обратились. Порядок: сначала ПОМЕСТИТЬ … ;, потом пакет, который из неё читает. Имя должно совпадать символ в символ.
❌ Остатки «на сейчас», хотя нужна дата в прошлом
Дата попала в ГДЕ или не попала в Остатки(...). Дата виртуальной таблицы задаётся только в её параметрах: Остатки(&Дата, ...).
❌ Ошибка приведения типов при сравнении со складом/видом цен
У параметра неверный тип (например, «Строка» вместо «СправочникСсылка.Склады»). Тип параметра должен совпадать с типом измерения.
